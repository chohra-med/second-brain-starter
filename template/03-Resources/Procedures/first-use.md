# First use

Use after verified installation in one confirmed target. This is the owner for personalization, one useful result and continuation. Setup belongs to the source ONBOARDING contract; Home and maps only navigate.

## 1. Recover the current state

Read the installed root `AGENTS.md`, then follow [Context](context.md) and its required [manual route](../../00-Meta/AGENTS.md). Read only those scoped owners and the installation receipt/current state when resuming setup. Stop on contradictions or failed verification. Client and operating-system permissions still apply; these instructions do not grant access.

Reuse answers and evidence already available in this selected target or chat. Preserve personalized records and existing history. Repeated or interrupted setup fills only actual gaps; do not replay completed edits. For returning use, recover the saved Next action through Context and continue that work without asking setup questions whose answers already exist.

## 2. Only ask what is missing

Ask only missing goal, current work, desired output and constraints. Use these prompts only for unanswered parts:

- What would you like to learn or finish, and what work have you already started?
- What small saved result would be useful at the end of this session?
- What limits should we respect, such as time, available material or tools? Mark unknowns unknown; never invent a deadline, fact, decision or verification result.

If the user is undecided, offer the existing learn-one-idea example below: ask for a paragraph they want to understand and obtain their confirmation of its goal and output before continuing. Suggest the saved learning note and paragraph comparison; do not choose or write automatically. A project can be learning or planning; coding is optional.

## 3. Approve the exact personalization

Show the exact personalized-record plan: file paths, proposed edits, evidence/source and unknowns. Use the existing [Facts](../../01-Projects/Selected-Project/FACTS.md), [Roadmap](../../01-Projects/Selected-Project/roadmap.md), [Decisions](../../01-Projects/Selected-Project/Decisions.md), [Progress](../../01-Projects/Selected-Project/progress.md) and [Daily task plan](../../00-Meta/Daily-Task-Plan.md) as state owners, only when their actual gaps require edits.

Obtain approval for that exact plan before edits. Preserve exact preimages and check current bytes for concurrent edits; stop on conflict. Append history rather than replacing it. Check approved edits against the plan. Existing personalized values stay intact unless the user explicitly approves a change.

The installer receipt rollback covers only its transaction. It does not automatically undo later personalization or artifacts. Keep their separate preimages and agree recovery before editing user-owned work.

## 4. Agree one useful artifact

Agree one small artifact, its exact file, scope and falsifiable check. Obtain approval for that artifact plan before producing it. Read the selected project's rules before touching its files. Use [Capture](capture.md) to record the outcome, owner, evidence required and next action in the roadmap.

Produce the approved artifact, run the agreed check and keep observable evidence. An offered task, blank template or promised result is not completed work. A failed check leaves the outcome Open or In progress.

## Noncoding example: learn one idea

This is an example to adapt with the user, not evidence of completed work.

- Goal: understand one idea from a user-provided paragraph in 15 minutes.
- Artifact: `01-Projects/Selected-Project/learning-note.md`, with the idea in plain language, one example and one next action.
- Scope: only the supplied paragraph; unsupported details stay unknown.
- Check: compare the note with that paragraph, identify the supporting sentence for each claim and confirm an actionable next step. Record the actual check result.
- PARA: the note belongs in Projects because this learning outcome has a finish line; reusable reference belongs in Resources and inactive work in Archives.
- CODE: Capture the paragraph and task; Organize them with this project; Distill the idea and example; Express them as the checked note and next action.

Follow the same personalization and artifact approvals above. See [PARA + CODE](../PARA-CODE.md) for definitions.

## 5. Close with evidence

Follow [Close](close.md). Record Done, Verified, Open and Next in existing progress, and reconcile the roadmap with actual evidence. Done means produced; Verified means the agreed check passed. Keep unresolved work visible. Show the artifact path and check result to the user.

## 6. Continue in a NEW chat

Start a new chat in the installed target. Read root `AGENTS.md` manually if the client has not confirmed loading it, then read `00-Meta/AGENTS.md` and the owners required by [Context](context.md). Recover the goal, constraints, output evidence and Next from those files, not the previous chat's memory. Name any contradiction and stop a success claim until it is resolved.

A same-chat reread is rehearsal. A synthetic walkthrough is fixture evidence. Fresh-client acceptance and authenticated discovery remain unverified until separately observed.
