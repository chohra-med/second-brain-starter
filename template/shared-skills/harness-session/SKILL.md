# Harness session

Use this when the person wants the corrections in this chat turned into fixes at the source, so the next session cannot make the same miss. The person can also invoke it as `/harness-session dry`, which prints the table and writes nothing.

Do not use this when:

- One confirmed miss needs one bounded rule. Use `second-brain-learning`.
- The session needs its records written. Use `end-session`, which can run this first.
- The person only wants the artifact they pointed at fixed. Fix it; this skill is for the generator behind it.

Read and follow `03-Resources/Procedures/harness-session.md`. That procedure owns the steps, the cause table, where each fix may go and the record to write. This skill only names when to use it.
