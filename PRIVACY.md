# Privacy boundary

Second Brain Starter is a local source package. Its initializer reads only the package manifest and the managed files it names. It does not recursively read a parent folder, inspect unrelated project files, read `.env` files or credentials, or send project content anywhere. The one exception is `connect`, described in the next paragraph.

`connect` reads only the repository you name, and only these things. At the repository root it checks by name and type whether these exist: the files `AGENTS.md`, `CLAUDE.md`, `CONTRIBUTING.md`, `RULES.md` and `SPEC-HARNESS.md`; the folders `ai_rules/` and `.memory/`; and the harness receipt `.claude/agents/.init-synthesis.json`. It lists the names in `.claude/agents/` and keeps the ones that match `sdd-*.md`. It checks whether `.git/` and `.git/config` exist. When `.git/config` is a regular file, it reads the `origin` URL from it. It checks whether each path it plans to write already exists, and it reads those bytes only to compare their hashes. It never prints or stores those bytes. It never lists or reads the contents of a sibling or parent folder, or of another repository. If `.git/config` exists but is not a regular file, `connect` refuses that repository. Verify reads the bytes of the staged files it wrote, only to compare their hashes. Apart from `.git/config` and those comparisons, `connect` reads no repository file contents.

The installer rejects unsafe targets, target escape, symlinked destination ancestors, unmanaged root loaders, and ordinary differing managed files. These are filesystem checks performed by the initializer. For the repository you name, `connect` applies the path-safety checks: it refuses a path with a symlink in it, the workspace itself, a folder inside the workspace, a folder that contains the workspace, the home directory, the filesystem root and the source copy. It never overwrites a file in the repository. A file that already exists there is kept and listed. Markdown instructions for an AI client are different: they guide a client that has already been given local-file access. They do not grant access, sandbox a client, enforce compliance, or support every future client version.

The installed target stores state, backups, and transaction-scoped rollback receipts under `.second-brain/`. Those local records include managed relative paths, hashes, and receipt identifiers. Connection records, connect receipts and connect pending records also hold the absolute path of the workspace and of each repository you explicitly connected with `connect`. Those paths can include your home folder. A connection also has a `Connection.md` file in its folder under `01-Projects/`, inside the workspace. That file holds the repository path, the remote, the rule-file names found, and the Spec Harness version and commit. The remote is the `origin` URL with credentials, query and fragment removed. A remote the parser does not recognise is recorded as `unknown`. Git writes a URL that contains `#` in quotes, and the loader does not read quoted values, so a remote written that way by git is recorded as `unknown`. A hand-written, unquoted URL is parsed and stripped. Apart from these fields, nothing from a repository is recorded, and no file contents are. The tool does not inspect the recorded names or paths for sensitive content. Those records stay on your machine and are not part of the shipped template. Folder names can carry client names, and the tool does not check them.

Sharing or committing the workspace folder shares those paths and the `Connection.md` files with whoever receives it. Roll a connection back before you share a copy, or share the workspace only with people who may know those paths.

This package has no telemetry, analytics, network service, global install, background process, or permission change. Node.js runs the initializer from the source copy you choose. This package runs locally and sends nothing anywhere. Once your AI client reads a repository's files, what it sends to its model provider is governed by that client and its settings, not by this package. Before sharing a modified copy, run the package scanner and review the complete reported path list; the scanner reports rules and relative paths only, never matched secret text.

Keep local projects private when they contain private information. A plain Markdown workspace can be copied as easily as any other local files.
