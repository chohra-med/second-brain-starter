# Privacy boundary

Second Brain Starter is a local source package. Its initializer reads only the package manifest and the managed files it names. It does not recursively read a parent folder, inspect unrelated project files, read `.env` files or credentials, or send project content anywhere. The one exception is `connect`, described in the next paragraph.

`connect` reads only the repository you name, and only these things. At the repository root it checks by name and type whether these exist: the files `AGENTS.md`, `CLAUDE.md`, `CONTRIBUTING.md`, `RULES.md` and `SPEC-HARNESS.md`; the folders `ai_rules/` and `.memory/`; and the harness receipt `.claude/agents/.init-synthesis.json`. It lists the names in `.claude/agents/` and keeps the ones that match `sdd-*.md`. It checks whether `.git/` and `.git/config` exist. When `.git/config` is a regular file, it reads the `origin` URL from it. It checks whether each path it plans to write already exists, and it reads those bytes only to compare their hashes. It never prints or stores those bytes. It never lists or reads the contents of a sibling or parent folder, or of another repository. If `.git/config` exists but is not a regular file, `connect` refuses that repository. Verify reads the bytes of the staged files it wrote, only to compare their hashes. Apart from `.git/config` and those comparisons, `connect` reads no repository file contents.

The installer rejects unsafe targets, target escape, symlinked destination ancestors, and ordinary differing managed files. It appends the managed block to a root `AGENTS.md` or `CLAUDE.md` that has no install record. It refuses to change a loader file whose comment is broken: a comment that is never closed, or a comment that names the tool and is not the one clean managed block, stops the install. A plain sentence that names the tool, outside any comment, does not stop it. `.gitignore` follows the same rule, with a line that starts with `#` as its comment, and only a `#` line shaped like a marker counts. A root `AGENTS.md`, `CLAUDE.md` or `.gitignore` that is not UTF-8 text stops the install too. The tool cannot recognise every possible damage, so read the plan before you approve it. These are filesystem checks performed by the initializer. For the repository you name, `connect` applies the path-safety checks: it refuses a path with a symlink in it, the workspace itself, a folder inside the workspace, a folder that contains the workspace, the home directory, the filesystem root and the source copy. It never overwrites a file in the repository. A file that already exists there is kept and listed. Markdown instructions for an AI client are different: they guide a client that has already been given local-file access. They do not grant access, sandbox a client, enforce compliance, or support every future client version.

The installed target stores state, backups, and transaction-scoped rollback receipts under `.second-brain/`. Those local records include managed relative paths, hashes, and receipt identifiers. Connection records, connect receipts and connect pending records also hold the absolute path of the workspace and of each repository you explicitly connected with `connect`. Those paths can include your home folder. A connection also has a `Connection.md` file in its folder under `01-Projects/`, inside the workspace. That file holds the repository path, the remote, the rule-file names found, and the Spec Harness version and commit. The remote is the `origin` URL with credentials, query and fragment removed. A remote the parser does not recognise is recorded as `unknown`. Git writes some URLs in quotes (for example, when they contain `#` or `;`), and the loader does not read quoted values, so those are recorded as `unknown`. A hand-written, unquoted URL is parsed and stripped. Apart from these fields, `connect` records nothing from a repository. It records no file contents. The tool does not inspect the recorded names or paths for sensitive content. Those records stay on your machine and are not part of the shipped template. Folder names can carry client names, and the tool does not check them.

**Quick start.** The quick start procedure (`03-Resources/Procedures/quick-start.md`) gives instructions to your AI client. It is not a command in this package. For one repository you name, the client reads only these items, when they exist: `AGENTS.md`, `RULES.md`, `CONTRIBUTING.md`, the folders `ai_rules/` and `.memory/`, and `README.md`. `connect` does not check `README.md`; the client reads it under this procedure. This package does not open those files and sends nothing. The client sends what it reads to its model provider, under that client's own settings. After you approve the exact text, the client writes three drafts into the project folder in your workspace: `FACTS.md`, `roadmap.md` and a first entry in `progress.md`. Those three files are not in the privacy block, so git tracks them, and a pushed or shared workspace carries them. `connect` creates that project folder from the template files before the drafts are written.

Sharing a copy of the workspace folder shares those paths and the `Connection.md` files with whoever receives it. The privacy block makes git ignore `Connection.md` by default, but a copy or an archive still includes it. Roll a connection back before you share a copy, or share the workspace only with people who may know those paths. The privacy block also ignores `00-Meta/Profile.md` and `00-Meta/Daily-Task-Plan.md`. A clone of your workspace made with git will not contain those two files, so the links to them on Home will not resolve in that clone until you add an exception line or copy the files.

The starter's own code, which is the installer and the starter's own files, has no telemetry, analytics, network service, global install, background process, or permission change. Node.js runs the initializer from the source copy you choose. The starter's own code runs locally and sends nothing anywhere. Bundled third-party folders are not the starter's own code. The scripts in the bundled `skill-creator` folder are the exception, described in the next paragraph. Once your AI client reads a repository's files, what it sends to its model provider is governed by that client and its settings, not by this package. Before sharing a modified copy, run `node --test`, which includes the package scan. If the scan fails, the test named `the real source root, vendored bytes included, passes the package scanner against FILE-ALLOWLIST.txt` lists each finding as a rule and a relative path, for example `UNALLOWLISTED_MEMBER .DS_Store`. Review that complete list before you share anything. The scan reports rules and relative paths only, never matched secret text.

**Optional skill-creator scripts.** The installer copies the bundled `skill-creator` folder into your workspace unchanged. That folder holds optional Python scripts. The installer never runs them. A person can run them. An assistant that uses the `skill-creator` skill is told by that skill to run them as normal steps, so they can run without you typing a command. When they run, they do the following:

- They call your Claude client. The client is the `claude -p` command-line tool. It sends the test prompts and the text of your skill to your model provider (`scripts/run_eval.py` and `scripts/improve_description.py`). `run_eval.py` also writes a temporary command file into `.claude/commands/` in your project, and deletes it after each test.
- They serve a review page on `127.0.0.1`, which is your own machine only (`eval-viewer/generate_review.py`). The default port is 3117. Before the page starts, they send a stop signal to every process listening on that port, not only to this tool. This needs `lsof`. Without it, the tool prints a note and stops nothing. If the port is still busy, the page uses another free port on `127.0.0.1`.
- They open your browser at the review page (`eval-viewer/generate_review.py`), and at the live report when the loop runs (`scripts/run_loop.py`).
- By default, the loop writes its live report to your system's temporary folder (`scripts/run_loop.py`).
- The report page loads fonts from Google when you open it, so your browser contacts Google (`scripts/generate_report.py`).
- The skill tells the assistant to start the review page and the optimization loop in the background (`SKILL.md`). They keep running after the step that started them.

If you do not want any of this, do not use the `skill-creator` skill. You can also remove its folders from `.claude/skills/` and `.agents/skills/`. If you do, `verify` lists the removed files as `MISSING` and ends with `Verification: FAILED`. That is the expected result of removing the folder. If another service uses port 3117, the review page stops that service when it starts.

Keep local projects private when they contain private information. A plain Markdown workspace can be copied as easily as any other local files.
